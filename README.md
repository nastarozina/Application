# Ne-Avito — Веб-приложение для просмотра и размещения объявлений

Веб-приложение для просмотра и размещения объявлений о продаже товаров. Система позволяет создавать объявления с названием, описанием, категорией и фотографиями, просматривать список опубликованных объявлений и открывать подробную информацию о выбранном объявлении.

Backend построен на Spring Boot и разделён на микросервисы для работы с объявлениями и категориями. Для хранения данных используется MongoDB, для хранения изображений — S3-совместимое объектное хранилище MinIO. Взаимодействие frontend с backend осуществляется через единый входной шлюз `inbound-gateway`.

## Функциональные возможности

- Просмотр списка объявлений.
- Просмотр подробной информации об отдельном объявлении.
- Создание объявлений.
- Поддержка иерархии категорий с родительскими и дочерними элементами.
- Выбор нескольких изображений при создании объявления.
- Предварительный просмотр выбранных фотографий.
- Удаление выбранных изображений до отправки формы.
- Загрузка изображений в MinIO с использованием предварительно сформированных URL загрузки.
- Сохранение объявлений и информации о связанных изображениях в MongoDB.
- Проверка обязательных полей и допустимости изображений.


### Планируемые возможности

- **Регистрация и авторизация пользователей через Keycloak.**
- **Редактирование и удаление своих объявлений через пользовательский интерфейс.**
- Поиск объявлений по названию и фильтрация по категории.
- Чат между покупателем и продавцом в реальном времени.
- Уведомления, избранное и отзывы о продавцах.

## Архитектура проекта

Приложение состоит из frontend, нескольких backend-сервисов и инфраструктурных компонентов.

| Компонент | Назначение |
|---|---|
| `banner-api` | Создание, получение и обновление объявлений, обработка связанных изображений |
| `category-api` | Получение и обработка категорий объявлений |
| `inbound-gateway` | Единая точка входа для запросов frontend и маршрутизация к backend-сервисам |
| MongoDB | Хранение объявлений, категорий и сведений об изображениях |
| MinIO | Хранение файлов изображений |
| Keycloak | Управление идентификацией пользователей в рамках планируемой интеграции |
| PostgreSQL | Хранение данных инфраструктуры Keycloak |
| React frontend | Пользовательский интерфейс приложения |

Взаимодействие компонентов:

1. Пользователь работает с веб-интерфейсом React.
2. Frontend отправляет запросы через `inbound-gateway`.
3. Gateway направляет запросы в соответствующий backend-сервис.
4. `banner-api` взаимодействует с MongoDB и сервисом категорий.
5. При загрузке фотографий frontend получает URL загрузки от backend и передаёт файлы в MinIO.
6. Backend сохраняет сведения об изображениях, связывая их с соответствующим объявлением.

## Системные требования

Для разработки и запуска приложения необходимы:

- ОС Windows, Linux или macOS с поддержкой используемых инструментов.
- JDK, соответствующий версии Java, указанной в Gradle-конфигурации backend.
- Gradle Wrapper, поставляемый с backend-проектом.
- Node.js и npm для сборки frontend.
- Docker и Docker Compose для запуска инфраструктуры и контейнеризированных сервисов.
- Свободные сетевые порты, предусмотренные конфигурацией развёртывания.
- Достаточное свободное место на диске для исходного кода, образов контейнеров, базы данных и файлов изображений.

Для запуска всех компонентов рекомендуется использовать Docker Compose. Для локальной разработки отдельных сервисов необходимо предварительно запустить их зависимости.

## Инструкция по запуску

### Шаг 1. Клонирование репозиториев

```bash
git clone https://github.com/nastarozina/Application.git
git clone https://github.com/nastarozina/frontend.git
```

### Шаг 2. Сборка backend

Перейдите в каталог backend:

```bash
cd Application
```

Соберите необходимые Gradle-проекты. К примеру:

```powershell
.\gradlew.bat :banner-api:build
```

Фактические имена Gradle-проектов должны соответствовать настройкам `settings.gradle` репозитория.

### Шаг 3. Запуск инфраструктуры

Предварительно для каждого Gradle-проекта соберите докер образ командой

```bash
.\gradlew bootBuildImage
```

Перейдите в каталог с конфигурацией развёртывания:

```bash
cd deployment
```

Запустите компоненты, определённые в Docker Compose:

```bash
docker compose up -d
```

Проверьте состояние контейнеров:

```bash
docker compose ps
```

При необходимости просмотрите журналы:

```bash
docker compose logs -f
```


### Шаг 4. Сборка frontend

В отдельном терминале перейдите в каталог frontend\ne-avito:

```bash
cd frontend\ne-avito
```

Установите зависимости:

```bash
npm install
```

Выполните production-сборку:

```bash
npm run build
```

Для запуска frontend в режиме разработки:

```bash
npm run dev
```

После запуска откройте адрес, указанный Vite в терминале. В стандартной конфигурации это `http://localhost:5173`.

### Шаг 5. Проверка работоспособности

1. Убедитесь, что контейнеры backend-сервисов, MongoDB и MinIO запущены.
2. Откройте frontend в браузере.
3. Проверьте загрузку списка объявлений.
4. Откройте страницу отдельного объявления.
5. Проверьте загрузку списка категорий.
6. Перейдите к созданию объявления.
7. Заполните название и описание, выберите категорию и добавьте несколько изображений.
8. Отправьте форму и убедитесь, что объявление создано.
9. Проверьте наличие загруженных файлов в MinIO и соответствующих сведений в MongoDB.

Для остановки контейнеров выполните из каталога `deployment`:

```bash
docker compose down
```

Команда останавливает и удаляет контейнеры, но обычно сохраняет данные в именованных томах. Не удаляйте тома, если необходимо сохранить данные.

## API

При стандартной конфигурации локального развёртывания запросы к backend выполняются через gateway по адресу `http://localhost:8080`.

Основные операции API:

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET` | `/api/banner` | Получение списка объявлений |
| `GET` | `/api/banner/{id}` | Получение объявления по идентификатору |
| `POST` | `/api/banner` | Создание объявления |
| `POST` | `/api/banner/{bannerId}/images/upload-url` | Получение URL для загрузки изображения |
| `POST` | `/api/banner/{bannerId}/images/{imageId}/complete` | Завершение операции загрузки изображения |
| `GET` | `/api/category` | Получение списка категорий |

Набор поддерживаемых методов и точные форматы запросов определяются контроллерами соответствующих сервисов.

API для обновления и удаления объявлений также может использоваться в соответствии с реализацией backend. Наличие серверной операции не означает, что соответствующая функция уже доступна через frontend.

## Тестирование

Для проверки приложения используются автоматизированные и ручные проверки.

Основные направления тестирования:

- Сборка backend-проектов с помощью Gradle.
- Сборка frontend с помощью `npm run build`.
- Проверка API получения списка объявлений и категорий.
- Проверка создания объявления и сохранения данных в MongoDB.
- Проверка обработки запросов с несуществующим идентификатором.
- Проверка валидации обязательных полей.
- Проверка допустимости изображений.
- Проверка загрузки нескольких изображений в MinIO.
- Проверка связи изображений с соответствующим объявлением.
- Проверка запуска сервисов через Docker Compose.
- Проверка автоматизированной сборки в GitHub Actions.

Для интеграционных тестов backend могут использоваться Testcontainers для запуска MongoDB и WireMock для имитации ответов внешних сервисов.

Результаты сборки и автоматизированных проверок доступны во вкладке [GitHub Actions](https://github.com/nastarozina/Application/actions).

## Разработка и внесение изменений

Для организации разработки используется Git с функциональными ветками и Pull Request.

Рекомендуемый порядок работы:

1. Создать задачу с описанием требуемого изменения.
2. Создать отдельную ветку, например `feature/14-s3-image-storage`.
3. Реализовать изменение и зафиксировать его коммитами.
4. Выполнить сборку и необходимые тесты.
5. Создать Pull Request и проверить результаты автоматизированной сборки.
6. После проверки объединить изменения с целевой веткой.
